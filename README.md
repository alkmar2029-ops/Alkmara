# نظام الحضور والإدارة المدرسية

منصة مدرسية مبنية بـ Next.js لربط حضور أجهزة ZKTeco بسير العمل اليومي للمدرسة. تشمل المنصة الحضور اليومي والحصصي، بوابة المعلم، الاستئذان والمخالفات، الإرشاد والحالات، التقارير، ورسائل واتساب.

## المتطلبات

- Node.js 20 أو أحدث
- npm 10 أو أحدث
- مشروع Supabase مهيأ بالمخطط والترحيلات الموجودة في `supabase/`
- جهاز ZKTeco على شبكة يمكن للخادم الوصول إليها عند استخدام المزامنة الفعلية

## التشغيل المحلي

```bash
npm ci
cp .env.production.example .env.local
npm run dev
```

على Windows PowerShell استخدم:

```powershell
Copy-Item .env.production.example .env.local
npm run dev
```

بعد ضبط القيم الحقيقية محلياً، افتح `http://localhost:3000`. لا ترفع ملف `.env.local` إلى Git.

## أوامر الجودة والبناء

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

تشغّل GitHub Actions هذه الفحوص آلياً عند كل طلب دمج وعند الدفع إلى الفرع الرئيسي.

## متغيرات البيئة

الحد الأدنى لتشغيل التطبيق:

| المتغير | الغرض | سري؟ |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | رابط مشروع Supabase | لا |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | المفتاح العام المقيّد بسياسات RLS | لا |
| `SUPABASE_SERVICE_ROLE_KEY` | عمليات الخادم الإدارية التي تتجاوز RLS | نعم |
| `WORKER_SECRET` | توثيق مهام المزامنة الداخلية | نعم |
| `NEXT_PUBLIC_PORTAL_URL` | الرابط العام لبوابة المعلم | لا |
| `NEXT_PUBLIC_TEACHER_ONLY` | يقصر النشر على بوابة المعلم عند ضبطه على `true` | لا |

إعداد أجهزة الحضور الاختياري:

| المتغير | القيمة الافتراضية/الغرض |
| --- | --- |
| `ZK_DEFAULT_PORT` | منفذ الجهاز، عادة `4370` |
| `ZK_DEFAULT_CMD_PORT` | منفذ الأوامر، عادة `5200` |
| `ZK_CONNECTION_TIMEOUT` | مهلة الاتصال بالمللي ثانية |
| `ALLOWED_DEVICE_CIDRS` | نطاقات CIDR المسموح الوصول إليها، مفصولة بفواصل |
| `ALLOWED_DEVICE_IP_PREFIXES` | بادئات IP قديمة اختيارية؛ يفضّل CIDR |

تستخدم سكربتات smoke/load متغيرات اختبار منفصلة مثل `SMOKE_BASE_URL` و`SMOKE_ADMIN_EMAIL` و`SMOKE_ADMIN_PASSWORD`. ضعها في بيئة محلية أو سرية في CI، ولا تكتب بيانات اعتماد حقيقية في المستودع أو السجلات.

> ملف `.env.production.example` قالب فقط. استبدل القيم الوهمية داخل `.env.local` أو إعدادات منصة النشر، ولا تستخدم مفتاح service-role في كود المتصفح.

## بنية المشروع

```text
app/                  صفحات Next.js ومسارات API
components/           مكونات الواجهة المشتركة
lib/                  منطق الأعمال، التحقق، التكاملات، والمساعدات
public/               الأصول العامة وملفات PWA
scripts/              فحوص التشغيل والصيانة والترحيل
supabase/migrations/  ترحيلات قاعدة البيانات وسياسات RLS
tests/                اختبارات الوحدات للدوال النقية
types/                تعريفات TypeScript المشتركة
```

## قاعدة البيانات والنشر

في مشروع جديد فارغ، طبّق `supabase/schema.sql` مرة واحدة بوصفه خط الأساس، ثم طبّق ملفات `supabase/migrations/` بالترتيب. لا تُعِد تطبيق ملف الخط الأساس على قاعدة قائمة؛ على البيئات القائمة طبّق الترحيلات الجديدة فقط. شغّل `node scripts/migration-order-check.mjs` قبل النشر، وطبّق الترحيلات أولًا على بيئة تجريبية. راجع `DEPLOY_VERCEL.md` لتفاصيل نشر بوابة المعلم على Vercel. احتفظ بنسخة احتياطية قبل الترحيلات، واختبر سياسات RLS بحسابات من كل دور.

### فتح عام دراسي جديد

بعد تطبيق ترحيل `20260901010000_academic_year_rollover.sql`، يستخدم المدير العام صفحة **لوحة التحكم ← فتح عام دراسي**. تعرض الصفحة معاينة قبل التنفيذ، ثم تغلق العام الحالي وتحفظ قيد كل طالب فيه، وترقّي الطلاب، وتؤرشف الخريجين، وتفتح قيود العام الجديد داخل معاملة واحدة. لا تُحذف سجلات الحضور أو الملاحظات أو الحالات. التراجع متاح لمدة 24 ساعة فقط ما لم يبدأ تسجيل بيانات جديدة. بعد الافتتاح راجع الشعب والإسنادات والجداول، وأعد إرسال الطلاب إلى أجهزة البصمة.

## ملاحظات أمنية

- `SUPABASE_SERVICE_ROLE_KEY` و`WORKER_SECRET` أسرار خادمية فقط.
- بيانات الطلاب وسجلات الأجهزة معلومات حساسة؛ المجلد `device-data/` وملفات البيئة مستثناة من Git.
- قيد عناوين أجهزة الحضور باستخدام `ALLOWED_DEVICE_CIDRS` في بيئات الإنتاج.
- يحرس اختبار ثابت استخدام service-role في مسارات API؛ أي مسار عام جديد يحتاج مراجعة أمنية وإضافة صريحة للقائمة المسموحة.
- شغّل `npm audit` وحدث الاعتماديات بانتظام بعد التحقق في بيئة تجريبية.
